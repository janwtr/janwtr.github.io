Animasi Proses DHCP (DORA) dan Resolusi DNS

Materi interaktif Jaringan Komputer — jalankan langkah demi langkah untuk memahami alur komunikasi jaringan.

DHCP (Dynamic Host Configuration Protocol) memungkinkan client mendapatkan konfigurasi IP secara otomatis dari server melalui 4 tahap yang disingkat DORA: Discover, Offer, Request, Acknowledge.

Perhatikan bahwa langkah 1 (Discover) dan langkah 3 (Request) sama-sama dikirim sebagai broadcast — ini sering disalahpahami sebagai unicast, padahal Request perlu broadcast agar server DHCP lain yang tidak terpilih juga tahu dan bisa menarik kembali tawarannya.

BROADCAST DHCPDISCOVER

Langkah 1 dari 4: DHCPDISCOVER

Client belum memiliki alamat IP (0.0.0.0), sehingga ia mengirim paket DHCPDISCOVER sebagai broadcast ke alamat tujuan FF:FF:FF:FF:FF:FF agar semua server DHCP di jaringan lokal menerimanya.

⚠️ Miskonsepsi umum: Banyak yang mengira DHCPREQUEST dikirim langsung (unicast) ke server yang dipilih. Padahal ini tetap broadcast, supaya DHCP server lain yang ikut menawarkan IP tahu bahwa tawaran mereka tidak dipilih dan bisa membebaskan kembali alamat tersebut.

Resolusi DNS menerjemahkan nama domain (mis. www.example.com) menjadi alamat IP. Client mengirim satu query rekursif ke resolver (biasanya milik ISP), lalu resolver melakukan serangkaian query iteratif ke server Root, TLD, dan Authoritative.

Bedanya: query rekursif (client→resolver) meminta jawaban akhir langsung, sedangkan query iteratif (resolver→root/tld/auth) hanya meminta "rujukan" (referral) ke server berikutnya — ini poin ujian yang sering keliru.
